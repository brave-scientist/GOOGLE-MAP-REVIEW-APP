    12→## Executive Summary
    13→
    14→- **The marketing landing page (`app/(marketing)/page.tsx`, `LiveDemo`, `BeforeAfter`, `TestimonialCarousel`, `PricingToggle`, `StatCounter`, `ScrollReveal`, `LogoCarousel`) is genuinely polished** — custom awning-stripe motif, branded ink/cream/brass/coral palette, Space Grotesk display font, hand-rolled scroll-reveal + IntersectionObserver animations, interactive live demo with typewriter effect, animated stat counters, dot-nav testimonial carousel. This is the strongest part of the codebase and is closer to a "premium $50k feel" than the app shell.
    15→- **The authenticated app shell (`(app)/dashboard`, `reviews`, `requests`, `settings`, `billing`, `org-dashboard`) is functional but visually flat** — plain cards with thin borders, no charts, no skeletons, no toasts, no animations, no icon library (uses unicode `★☆✓` and emojis), no design-system primitives. Reads as "MVP that works," not "premium SaaS."
    16→- **One P0 production-breaking bug:** `OnboardingForm.tsx` calls `POST /api/businesses/${businessId}/connect/facebook`, but **no such route exists** in `app/api/businesses/[id]/connect/`. The Facebook connect button is dead — every new user who tries to connect Facebook gets a 404.
    17→- **One P0 revenue bug:** the Enterprise plan ($249/mo) is sold in `BillingManager.tsx` and on `/solutions/[slug]` but **both `/api/billing/checkout` and `/api/billing/manage` reject `enterprise`** with `if (plan !== "starter" && plan !== "pro")`. Clicking "Upgrade to Enterprise" returns 400. Enterprise tier is unreachable.
    18→- **One P1 multi-tenant bug:** `/api/billing/manage` uses `businesses[0]` instead of the active business from the cookie. Multi-location (Enterprise) users who switch to location #2 and click "Cancel subscription" will cancel location #1's subscription.
    19→- **Duplicate H1 on `/requests`** — `requests/page.tsx` renders `<h1>Review Requests</h1>` and `RequestsManager.tsx` renders another `<h1>Review Requests</h1>`. SEO + a11y issue.
    20→- **Three invalid Tailwind classes silently no-op:** `space-y-22` and `mb-22` (default scale stops at `12` / jumps to `14, 16, 20, 24`; `22` is invalid) in `(marketing)/page.tsx`, and `duration-400` (default scale jumps `300 → 500`) in `TestimonialCarousel.tsx`. Also `prose prose-invert` in `terms/page.tsx` requires `@tailwindcss/typography`, which is **not installed**.
    21→- **No shared marketing layout** — each marketing page re-implements its own header/footer. `/vs/birdeye`, `/vs/podium`, `/privacy`, `/terms` have no top nav and no footer (dead-end pages).
    22→- **No `error.tsx`, `loading.tsx`, or `not-found.tsx`** anywhere in the route tree — no branded 404, no Suspense fallbacks, no error boundaries.
    23→- **Accessibility is uneven:** login + onboarding forms associate labels correctly via `htmlFor`/`id`, but `RequestsManager`, `SettingsForm`, `LiveDemo` use sibling `<label>` elements with no association; `LiveDemo`'s clickable stars are `<span onClick>` with no keyboard handler; `AppNav`'s account dropdown has no `aria-expanded`, no Escape, no outside-click dismiss.
    24→- **Heavy mock-mode leakage:** OnboardingForm hardcodes `MOCK_GOOGLE_LOCATIONS[0]` (always "The Copper Spoon (Mock)") regardless of the business name the user typed; `LogoCarousel` and `TestimonialCarousel` ship "PLACEHOLDER" comments; the marketing page advertises "Built for single-location businesses" but the org-dashboard + Enterprise plan exist for multi-location. Inconsistent positioning.
    25→- **Wasted work:** `dashboard/page.tsx`, `reviews/page.tsx`, `requests/page.tsx` all call `const user = await getCurrentUser()` and never use the result (the `(app)/layout.tsx` already gates auth).

   146→## Top 10 Design Quality Gaps (vs. "Premium $50k Feel")
   147→
   148→1. **No icon library.** The entire UI uses unicode (`★ ☆ ✓ →`) and emojis (`🍕 ✦ ◎ ⬡ ▣ ◈ ◆ ❋`). A premium SaaS needs `lucide-react` or `@heroicons/react` for consistent, scalable iconography — especially in the app shell (nav, buttons, empty states, status badges).
   149→
   150→2. **No design-system primitives.** Every button is `<button className="rounded-lg bg-brass px-6 py-2.5 font-semibold text-ink...">` repeated ad nauseam. No `<Button variant="primary|secondary|ghost|danger">`, no `<Card>`, no `<Input>`, no `<Badge>`, no `<Tabs>`, no `<Modal>`, no `<Toast>`, no `<Skeleton>`, no `<EmptyState>`. This is the single biggest gap between the current state and a maintainable premium product.
   151→
   152→3. **No animations in the app shell.** The marketing page has scroll-reveal, stat counters, typewriter, carousels. The dashboard/reviews/requests/settings/billing pages have **zero animation** — no page transitions, no list stagger, no hover lifts, no loading skeletons. Feels static and dated.
   153→
   154→4. **No charts or data visualization.** The dashboard shows 4 plain number cards. The org-dashboard shows a plain HTML table. A premium review-management SaaS needs rating-trend lines, source breakdown (Google vs Facebook pie), response-time histograms, request-funnel bars (sent → clicked → reviewed). Currently zero data viz.
   155→
   156→5. **No loading skeletons or optimistic updates.** Every mutation just changes button text to "Saving…" / "Sending…" / "Canceling…". No skeleton placeholders for initial page loads. No optimistic UI for quick-add (the new row appears only after `refresh()` completes).
   157→
   158→6. **No toast/notification system.** Success and error feedback are inline `<span>` tags below buttons. A premium SaaS needs a top-right toast stack (e.g., `sonner` or `react-hot-toast`) for "✓ Settings saved", "✓ Reply posted", "✗ Checkout failed".
   159→
   160→7. **No empty-state illustrations.** Empty reviews/requests show a plain `<p>No reviews yet.</p>`. Premium SaaS uses illustrated empty states (e.g., unDraw or custom SVG) with a clear CTA.
   161→
   162→8. **Inconsistent pricing surface.** The main landing page shows 2 plans (Starter, Pro). The `/solutions/[slug]` pages show 3 plans (Starter, Pro, Enterprise). The billing page shows 3 plans. The footer links to "vs Birdeye" and "vs Podium" but not to a pricing page. Enterprise is sold but unreachable (see bug #2).
   163→
   164→9. **Dead-end comparison pages.** `/vs/birdeye` and `/vs/podium` are bare text + table with no nav, no footer, no logos, no screenshots, no testimonials. They read as 2020-era SEO landing pages, not 2025 premium product pages.
   165→
   166→10. **No dark/light theme toggle.** The app is permanently dark (ink background). This is a valid design choice, but premium SaaS typically offers a light mode for accessibility and user preference. The `tailwind.config.ts` has no `darkMode` strategy configured.
